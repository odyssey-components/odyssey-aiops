# Go1 仿真任务

进入 Go1 的「仿真任务」，右上角点击「添加仿真任务」。选择已有模型和固定预设场景，填写任务名称、随机种子和仿真步数（50–500），提交后进入详情。

场景固定为六类：空旷场地、拐弯、窄路掉头、越过小坡、俯身穿过横梁、跳过低横梁。参数和通过条件使用内置默认值，只需选择场景，无需添加或填写场景参数；列表的「查看」独立打开三维场景弹窗，「详情」保留只读数值和通过条件。空旷场地仅用于仿真诊断。场景列表和按 ID 查询直接返回代码预设，不读写数据库场景表或预设文件。历史任务继续使用创建时的场景快照。

仿真与训练共用本地 Go 串行队列。排队和执行中的仿真均可取消；详情显示实际步数、日志、目标结果、机身高度与位置。完成后点击「查看仿真回放」，可以播放、拖动时间轴，并返回任务详情或列表。URL保存详情标识，支持刷新恢复。

仿真使用 MuJoCo CPU 物理（500Hz）与50Hz控制，模型只读，不启动训练或更新权重。视觉模型使用JAX CPU策略和真实深度相机帧，运动控制模型执行原两层tanh策略。相机/模型协议或依赖缺失时任务失败并记录原因，不生成替代轨迹。

Go1 Python环境需要安装本包及`simulation` extra，并配置固定版本机器人源码（沿用服务端`--go1-source`/`ODYSSEY_GO1_SOURCE`）。仿真不依赖训练环境的GPU就绪状态；源码commit仍须为`f4fb0d12ac68842c1567bf1de6f771ce8e6671b5`，模型文件必须无修改且摘要匹配已保存策略。

数据保存到`~/.odyssey/go1/simulations/<UUID>/`：任务记录、配置、模型/清单副本、结果和最多500帧回放；不修改原模型或场景。排队后输入快照变化会拒绝启动，失败/取消不暴露不完整回放。服务重启把未结束任务标记中断，不自动重新执行。

“任务已完成”表示仿真执行及结果保存完成，目标结果另行显示，例如“达到目标”“跌倒”“发生碰撞”“偏离道路”“达到步数上限”。回放根据已保存物理状态重建三维场景，不重新计算物理。右下角默认显示「机器人眼睛」画中画，随机器人姿态和时间轴同步变化。点击「机器人眼睛」可隐藏或重新显示小窗，主画面可自由旋转、缩放与跟随。

仿真完成后，任务目录的 `output/policy-input.mcap` 保存 50 Hz 策略调用记录。每步包含归一化的 float32 深度帧、机身观测、策略预处理后的机身状态、模型原始动作与限幅后施加的动作。文件元数据保存模型和机器人来源摘要、相机输入规格及仿真配置。所有新仿真都采集深度帧。非视觉模型使用默认相机规格（64 × 48、10 Hz），策略仍只接收机身观测。深度帧按控制步保存，相机未刷新时沿用上一帧。

「录制任务」集中显示仿真录制状态和 MCAP 是否就绪，可打开仿真详情或创建新的录制仿真。在「回灌任务」列表可直接点击「创建回灌任务」，选择已有完整录制的仿真与待测模型，也可从仿真详情发起。创建后进入独立的「回灌任务」详情。该标签默认显示回灌列表，详情可逐步比较动作并返回列表。任务沿用本地队列、模型快照和取消机制，要求待测模型和录制的机器人来源一致。视觉模型还要求录制含有规格匹配的深度帧，非视觉模型只读取机身观测。结果按步列出 12 个关节的原始动作和差值（待测减录制），并标记全程最大绝对动作差。待测动作不施加到物理仿真。动作差描述输出变化，碰撞、跌倒或到达目标仍由闭环仿真评估。历史仿真若没有 MCAP，须重新仿真后才能回灌。历史 MCAP 若缺少深度帧，仍可用于非视觉回灌，视觉回灌须重新录制。

创建仿真任务时可选择单个场景或已保存的场景集。场景集只创建一个任务，在同一模型快照下按顺序独立运行各场景，种子和步数上限应用于每个场景。详情显示各场景结果，回放弹窗可切换场景。每个场景的结果、轨迹及 MCAP 分别保存在任务的 `output/case-N/` 下。诊断场景单独展示且不计入通过率。回灌入口目前使用单场景仿真录制。

回灌详情按策略步查看待测模型的输入。机身向量取自待测模型实际使用的预处理结果，视觉模型的深度输入按当前步加载并以灰度展示。动作列沿用原录制模型输出、待测模型输出及差值。旧报告保留动作对比，重新回灌后才会生成观测数据。

Go1 模型库只列出通过上游协议校验的基础模型和已导入的公开策略。自训权重不进入模型库或新任务的模型选择器，训练记录与历史回放仍保留。回灌测试只接受兼容的视觉策略，模型库没有此类策略时无法从页面创建新的回灌测试。
