# 逐轮通关率折线图

训练页在任务开始后显示真实通关率曲线。横轴是轮次，纵轴固定为0–100%，第0轮表示训练前。新训练每完成一轮，都会实际运行评估并记录一个点；不会用动作正确率代替通关率，也不会根据两个采样点伪造中间轮次。

- 第一课：单张固定地图是否在步数上限内到达出口，结果为0%或100%，图名为「固定地图通关率」。它不是独立验证集。
- 第二至四课：使用已经准备好的64张验证地图，图名为「验证集通关率」。每轮评估相同的验证集合，测试集不参与逐轮检查或权重选择。

页面只显示图表、数值摘要和操作控件，不放教学长文。摘要中的「最新」对应最后一个已测轮次，「最佳」与「最佳轮次」取最高通关率首次出现的位置，「较初始」按百分点比较训练前后；旧任务没有第0轮数据时，不计算这个差值。

指针悬停或使用下方滑块的方向键、Home/End，可以查看某一个实际记录的轮次。训练仍在进行时，新点会随状态轮询出现；刷新页面可重新读取同一任务的指标。切换课时或启动新任务时，不混用上一任务的数据。

## 怎样分析？

曲线持续上升说明模型在这批验证地图上越来越能走完。曲线上下波动说明某些参数更新改善了一部分地图，同时也可能破坏原先会走的路线。训练动作正确率提高，不保证实际通关率每轮都提高。

比较最佳与最新，可以发现继续训练是否带来下降。输出权重按验证通关率最高的轮次选择，相同通关率保留更早的轮次，因此最终保存的模型不一定来自最后一轮。独立测试集只在选择后用于最终测量；验证通关率不能直接当作最终测试通关率。

## 保存与导出

「导出CSV」只导出已记录的实测点，包含轮次、总轮数、原始0–1通关率、评估地图数、数据分组，以及可用的训练损失和训练专家动作正确率。通关率和动作正确率是不同列，不是同一个指标。

完整逐轮数据还保存在run目录的 `report.json`：

- `validation` 保存第0轮及每一轮的通关率。
- `history` 保存每轮训练损失、动作正确率与通关率。
- `selected_epoch`（随机课程）记录验证选择的权重轮次。

服务端把结构化指标与显示日志分开保存。显示日志仍有长度上限，但指标不会跟着日志尾部截断而丢掉开头的点；取消或失败保留已经完成的测量。

旧任务只记录每10轮时，只能画出这些已有采样点和当时的显示精度，不能恢复没测过的轮次。新启动的训练才会每轮实际评估。每轮跑验证比之前每10轮一次更耗时，训练轮数相同不代表运行时间相同。
